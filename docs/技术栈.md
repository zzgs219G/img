三、请求消耗模型（重要）

用户打开页面不消耗 Worker 请求。

用户行为 消耗 Worker 请求
打开页面（HTML/CSS/JS） ❌ 0
加载图片、字体、图标 ❌ 0
刷新页面 ❌ 0
选图 ❌ 0
浏览器本地压缩 ❌ 0
生成文件名 ❌ 0
点“上传”调 /api/upload ✅ 1
Worker 内部 push 到 CNB 不计入用户请求

结论：一次上传 = 1 次 Worker 请求。页面浏览全部白嫖。

实现靠 wrangler.jsonc 的 run_worker_first: false：请求先匹配静态资源，命中直接返回，不执行 Worker；只有 /api/* 才进 Worker。

七、文件名规则

```text
img_YYMMDD_xxxxxx.webp
```

示例：

```text
img_260920_a3f9c1.webp
```

段 含义 示例
img 固定前缀 img（icon 前缀落 src/icons/）
YYMMDD 年月日 260920
xxxxxx 3 字节随机数的 6 位十六进制 a3f9c1
.webp 固定扩展名（GIF 除外） .webp

为什么这样设计：

· 文件名短，URL 干净
· 同一天约 1.9 亿种随机组合，撞名概率可忽略
· 不用查仓库，Worker 直接生成
· 看文件名就知道上传日期

八、格式与压缩规则

项 规则
允许输入 jpg / png / webp / gif / bmp / avif
输出格式 统一转 webp
GIF 例外 保持原样，不压缩、不转格式，动图不变
最大宽度 1920px（超过才缩放，不放大）
webp 质量 0.8
大小上限 10MB
压缩位置 浏览器端 Canvas
压缩时机 用户选图后、上传前
压缩请求消耗 0

十三、关键代码约定

压缩函数

```ts
// src/lib/compress.ts
export async function compressImage(
  file: File,
  options?: { maxWidth?: number; quality?: number }
): Promise<{ blob: Blob; width: number; height: number; ext: string }>
```

行为：

· 检测到 GIF → 直接返回原文件，ext = 'gif'
· 其他格式 → Canvas 压缩 → toBlob('image/webp', 0.8)
· 宽度超过 1920 → 等比缩放
· 宽度不超过 → 不放大

文件名生成

```ts
// src/lib/filename.ts
export function generateFilename(ext: string, type: 'img' | 'icon' = 'img'): string
// 返回：img_260920_a3f9c1.webp（type='icon' 时返回 icon_260920_xxxxxx.webp）
```

Worker 上传处理

```ts
// worker/index.ts
async function handleUpload(request: Request, env: Env): Promise<Response>
```

isomorphic-git push 核心

```ts
import git from 'isomorphic-git'
import http from 'isomorphic-git/http/web'

// 1. git.init

// 3. git.commit
```

十四、部署方式

Termux 装不了 wrangler，走 GitHub 自动部署：

1. 代码 push 到 GitHub
2. Cloudflare Dashboard → Workers & Pages → 连接 GitHub 仓库
3. Build command: npm run build
4. Deploy command: npx wrangler deploy
5. 环境变量在 Cloudflare 控制台配置

十五、Termux 环境限制

限制 影响 绕过方式
装不了 wrangler 不能本地 wrangler dev 用 GitHub 自动部署
装不了 workerd 同上 同上
装不了原生图片库（sharp） 不能 Worker 端压缩 压缩放浏览器端 Canvas
